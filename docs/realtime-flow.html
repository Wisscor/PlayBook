5. Registry State

The registry module holds a single in-memory dict _connections: dict[UUID, set[WebSocket]] (a defaultdict(set)). Below is the state after two users with two tabs each connect, and the changes when one tab disconnects.

registry.py connection.py

State after 2 users × 2 tabs connect:

Key (user_id)Value (set of WebSocket)Helper results
UUID-A (Alice) {ws_A_tab1, ws_A_tab2} connections_for(UUID-A) → 2 sockets
UUID-B (Bob) {ws_B_tab1, ws_B_tab2} connections_for(UUID-B) → 2 sockets

online_user_ids() → {UUID-A, UUID-B} |  send_to_user(UUID-A, frame) → sends to both ws_A_tab1 and ws_A_tab2

After Alice's Tab 1 disconnects:

StepFunction (file)Effect on _connections
1 on_disconnect (connection.py) Calls registry.unregister(UUID-A, ws_A_tab1)
2 unregister (registry.py) _connections[UUID-A].discard(ws_A_tab1)
Set still has ws_A_tab2 → key is not deleted
3 on_disconnect check (connection.py) connections_for(UUID-A) → {ws_A_tab2} (non-empty)
→ announce_presence(online=False) is NOT sent
KeyValueChange
UUID-A {ws_A_tab2} ws_A_tab1 removed; Alice still appears online
UUID-B {ws_B_tab1, ws_B_tab2} unchanged

If Alice's Tab 2 also disconnects (last tab):

StepFunctionEffect
1 unregister(UUID-A, ws_A_tab2) Set is now empty → del _connections[UUID-A]
2 on_disconnect check connections_for(UUID-A) → empty set
3 announce_presence (connection.py) send_to_user sends presence online=false to all contacts

online_user_ids() → {UUID-B} — Alice is now fully offline.

⚠ Not verified / Intentionally omitted

  • CLOSE_SESSION_ENDED (4003): Defined in frames.py but no code in the realtime package sends this close code. It is likely triggered by an external session-invalidation mechanism outside back/app/realtime/.
  • Ping interval "every 20 s": The comment in frames.py says "client → server every 20s" but the server code does not enforce this interval — it only replies with pong. The 20 s cadence is a client-side convention.
  • notify.py: This file (emit_notification) is called from outside the realtime package (e.g., follow/like handlers). It is included in the module map but not in the lifecycle or message diagrams since it is an external entry point.
  • REST endpoints (rest.py): Included in the module map only. The five REST routes (POST /conversations, GET /conversations, GET /conversations/{id}/messages, GET /notifications, POST /notifications/read, GET /notifications/count) are not part of the WebSocket flow.
  • Message body validation: MessageSend in schemas.py enforces min_length=1, max_length=2000 and str_strip_whitespace=True. This is handled by Pydantic's model_validate and raises ValidationError → invalid_frame error.
  • Database connection pooling / transaction isolation: Each session_maker() call creates an independent async session. The exact pool settings and transaction isolation level are defined in database.py, not examined here.
